# M7 — Starred Notes Feature

## Feature I picked
- Feature: Starred notes filter

## Plan from chat
- Starring a non-existent note — return 404; don't create it
- Empty starred list — show a "No starred notes" empty state, not a blank page
- Filter + star interaction — toggling a note's star while in "Starred" view should remove it from the list immediately, not leave a ghost entry
- In-memory reset — starring is lost on server restart; document this or warn the user if persistence is expected
- Concurrent toggles — two rapid clicks could desync; the toggle endpoint should return the new state so the UI can reconcile rather than assuming the flip happened

## Execute in Claude Code
- Branch: m5-task-1-tags-key
- One thing Claude flagged that the chat plan missed: The existing delete route used Jinja2's `loop.index0` to build the form action URL. That works fine when the full unfiltered list is rendered, but breaks silently when a filter is active — `loop.index0` reflects position in the *filtered* list, not the real index in `app.notes`, so deleting a note in Starred view would remove the wrong note. The fix was to pass `(idx, note)` tuples from the backend and use the real index in both the delete and star forms.

## Acceptance criteria
- `POST /notes/<idx>/star` toggles starred and returns 404 for a missing index
- `GET /?starred=true` shows only starred notes with a "No starred notes." empty state when none exist
- Delete works correctly from the Starred filter view (removes the right note)
